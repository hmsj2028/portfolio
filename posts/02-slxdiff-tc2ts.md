# slxdiff · TC2TS: 모델 변경 → 테스트 영향 분석 자동화

*2026.08 ~ 2026.09 · 슈어소프트테크 인턴 · 팀 프로젝트(도구 개발 담당)*

## 왜 필요했나

자동차 제어 알고리즘은 Simulink 모델(.slx)로 설계된다. 펌웨어가 매달 바뀌면 모델도 바뀌고 검증팀은 그때마다 세 가지를 손으로 해야 했다.

1. 모델에서 무엇이 바뀌었는지 찾기. 그런데 .slx는 MATLAB 라이선스가 있어야 열 수 있다
2. 바뀐 부분에 영향을 받는 테스트 케이스(TC)와 자동화 스크립트(TS) 추적하기
3. TC를 고친 뒤 TS로 다시 옮겨 적기

놓치면 검증 누락이고, 꼼꼼히 하면 시간이 많이 든다.

## 만든 것

### slxdiff: 라이선스 없이 모델 비교
- .slx 파일은 내부적으로 압축된 XML이라는 점을 이용해 MATLAB 없이 모델 구조를 읽는다
- 두 시점의 모델을 비교해 블록 추가·삭제, 파라미터 변경, 신호 연결 변경을 자동으로 찾는다
- 변경을 **기능 / 외관 / 파생**으로 나눠서 레이아웃만 바뀐 것과 진짜 로직 변경을 구분한다
- 결과는 브라우저에서 보는 HTML 뷰어(좌: 원본 트리, 우: 변경 모델)와 변경 리포트로 출력한다

예시 모델(차량 제어 기능 모음)로 원본 → 8월 → 9월 변경을 만들어 시험했다. 원본→9월 비교에서 1,155건이 나왔고 그중 로직에 영향을 주는 기능 변경은 222건이었다. 사람이 다 볼 필요 없이 이 222건만 보면 된다.

### 영향 분석: 변경점 → TC 자동 갱신
- slxdiff 결과를 압축한 JSON과 신호-TC 매핑을 LLM에 넣고 규칙 문서(프롬프트)대로 영향받는 TC를 찾게 했다
- 기계적으로 판단할 수 있는 항목(신호명 변경, 대기 시간 변경 등)은 자동 수정하고 바뀐 셀은 색으로 표시한다
- 정답지와 비교해 틀린 부분을 찾고 규칙을 고치는 과정을 반복해 정확도를 올렸다

### TC2TS: 테스트 케이스 → 자동화 스크립트 변환
- 사람이 읽는 TC 엑셀(검증 목적, 시험 전 조건, 시험 방법, 판정 조건)을 자동화 컨트롤러가 실행하는 TS 명령어로 변환한다
- 신호 설정, 대기 시간, 판정 조건(==, <, >) 같은 규칙 10가지를 정리해서 구현했다
- 18개 TC를 12초 만에 변환했고 18개 모두 오류 없이 변환됐다

## 어려웠던 점

- **변경의 "의미" 구분.** 블록 좌표만 움직여도 XML은 바뀐다. 이런 외관 변경을 걸러내지 않으면 리포트가 잡음으로 가득 차서 변경 종류를 나누는 규칙을 따로 만들었다.
- **자동 변환으로 안 되는 것 인정하기.** Description·Delay 중복, 변수 형태 신호값, 변속 반영 등은 자동화가 오히려 틀릴 수 있었다. 억지로 다 자동화하지 않고 "수동 확인 항목"으로 분리해 사용자에게 보여 주도록 했다.

## 배운 것

- 검증 도구는 "다 해 주는 것"보다 "사람이 볼 곳을 줄여 주는 것"이 더 쓸모 있다
- LLM을 쓸 때는 입력을 작게 정리하고(압축 JSON) 정답지와 비교하는 루프가 있어야 믿을 수 있다
