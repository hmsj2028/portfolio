# 사내 업무 자동화 크롬 확장

*2026.09 · 슈어소프트테크 인턴 · 개인 개발*

## 왜 만들었나

팀에서는 매일·매주 사내 그룹웨어와 프로젝트 관리 시스템에 들어가 같은 문서를 손으로 채웠다. 야근 식대 결의서, 장비 반출입 신청서, 파견비 신청서, 주간 타임시트 같은 것들이다. 하나는 5~10분이면 끝나지만 지급처 검색, 결재선 확인, 참조자 추가, 프로젝트 코드 입력을 매번 반복하다 보니 시간과 집중력이 계속 깎였다.

## 1차: Python + Selenium → 다시 만들기로

처음엔 tkinter 런처와 Selenium으로 만들었다. 동작은 했지만 불편한 점이 있었다.

- 전용 크롬 프로필을 띄우니까 원래 쓰던 브라우저 로그인을 못 쓰고 따로 로그인해야 했다
- exe 배포는 사내 보안 정책상 신뢰받기 애매하고 업데이트할 때마다 다시 배포해야 했다
- 자동화 창이 따로 떠서 지금 무슨 일이 진행 중인지 보기 어려웠다

그래서 **크롬 확장(Manifest V3)**으로 다시 만들었다. 사이드패널에서 도구를 고르고 값을 넣은 뒤 "자동 입력 시작"을 누르면, 지금 쓰는 브라우저 탭에서 바로 채워진다. 이미 로그인된 세션을 그대로 쓰고 설치는 폴더 하나 불러오면 끝이고 진행 과정이 눈에 보여서 언제든 멈출 수 있다.

## 구조

1. **사이드패널(UI)**: 도구와 값을 고르면 백그라운드로 실행 메시지를 보낸다
2. **백그라운드 서비스 워커**: 대상 탭을 찾거나 열고 지금 몇 번째 단계인지 `chrome.storage.session`에 기록한다
3. **콘텐츠 스크립트**: 실제 페이지에 들어가 DOM을 직접 조작한다. 값만 넣으면 사이트가 인식하지 못해서 `input`/`change` 이벤트까지 함께 발생시켰다

가장 까다로운 점은 자동화 도중 페이지가 여러 번 바뀐다는 것이었다(로그인 → 메인 → 작성 화면 → 팝업). 페이지가 바뀌면 스크립트 상태가 전부 사라진다. 그래서 단계를 저장해 두고 새 페이지의 스크립트가 뜨자마자 "이어서 할 일 있어?"라고 물어 이어받는 **상태 기계**로 만들었다.

## 부딪힌 문제

- **같은 단계가 두세 번 실행되는 버그.** 단계 알림이 여러 경로로 겹쳐 들어와 입력이 중복됐다. 실행 중 플래그로 막았는데, 잠금을 `await`로 오래 잡으면 다음 단계 메시지가 무시되는 문제가 또 생겨서 "다음 단계로 넘기는 호출은 기다리지 않는다"는 규칙으로 정리했다.
- **CSP에 막힌 스크립트.** 사이트 자체 함수를 부르려고 `<script>` 태그를 넣었더니 브라우저 보안 정책에 막혔다. `chrome.scripting.executeScript`로 페이지의 실제 실행 환경(main world)에서 호출하도록 바꿔 해결했다.
- **참조자 자동 판별.** 처음엔 참조자를 고정값으로 넣었는데, 실제 규칙은 "최종 결재자가 속한 조직의 한 단계 위 책임자"였다. 결재선 정보와 조직도 트리 구조를 분석해 자동으로 계산하게 만들었다.

## AI 코딩 도구를 쓰는 방식

사내 시스템이라 AI가 화면을 직접 볼 수 없다. 그래서 내가 개발자 도구로 실제 HTML 구조와 콘솔 로그를 복사해 주고 그 증거를 근거로 코드를 고치게 했다. 추측으로 고치고 또 추측하는 것보다 훨씬 빠르고 정확했다. 큰 기능은 바로 구현하지 않고 기존 코드 조사 → 설계안 검토 → 계획 정리 → 구현 순서로 진행했다.

## 결과와 배운 것

사이드패널 하나로 문서 4종을 자동 작성하고 참조자도 결재선을 분석해 알맞은 사람을 넣는다. 만들면서 확장 프로그램 구조, 메시지 전달, 브라우저 보안 정책, 실제 서비스 DOM을 분석해 안정적으로 자동화하는 법을 익혔다.

*사내 시스템 전용이라 코드와 화면은 공개하지 않습니다.*
