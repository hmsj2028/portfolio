# OS 신호 추출기

*2026.07 · 슈어소프트테크 인턴 · 개인 개발*

## 배경

자동차 부품사의 차량 플랫폼 제어기 검증 업무를 지원하면서 만든 도구다. 펌웨어가 업데이트되거나 변수가 바뀔 때마다, 검증 담당자는 수많은 신호 중 무엇이 바뀌었는지 Simulink 모델을 직접 열어서 하나씩 따라가야 했다. 시간이 오래 걸리고 누락이나 오독도 잦았다.

## 용어 정리: "OS 신호"

제어기 SW는 AUTOSAR 구조(애플리케이션 계층 ASW / RTE / BSW)를 따른다. 표준에서 OS는 태스크 스케줄링을 담당하고 신호를 정의하는 계층이 아니다. 실무에서는 OS 스케줄에 맞춰 주기적으로 돌며 CAN 신호를 주고받는 로직을 모델 폴더상 `os`로 묶어 관리했고 그래서 팀에서 "OS 신호"라고 불렀다. 표준의 정의와 현장 용어가 다를 수 있다는 걸 이때 알게 됐다.

## 만든 것

MATLAB으로 Simulink 모델을 자동으로 열고, 신호의 입력·출력 관계를 끝까지 추적해 엑셀로 정리하는 도구다.

- 상위 폴더만 지정하면 `os`, `rte` 등 관련 폴더를 재귀 탐색해서 모델과 데이터를 스스로 찾는다
- 모델 안의 `Swc_` 서브시스템을 찾아 들어가 실제 신호가 시작되는 지점까지 추적한다
- Goto/From, 게이트, 변환 블록을 여러 번 거쳐도 원본 신호 이름까지 따라간다
- 연결 안 된 신호(Ground), 상수, 여러 신호가 합쳐지는 경우를 구분해서 표시한다
- 여러 모델을 한 번에 처리하고 결과는 모델별 시트로 나눈 엑셀 하나로 낸다
- 진행률 창을 띄우고 문제가 생긴 부분만 로그로 남긴다

## 만든 방식

Claude Code로 요구사항을 프롬프트로 구체화하며 코드를 작성했고 실사용자 피드백(예: "입력이 여러 개인 경우도 넣어 달라")을 받아 v0.3부터 v0.6까지 기능을 넓혔다. 신호가 특이한 블록을 거치면 추적이 끊기는 경우가 있었는데, 실제로 끊기는 사례를 모아 예외 처리를 하나씩 추가해서 해결했다.

배포까지 고려해 소스를 pcode로 보호하고 실행용 .bat과 사용설명서를 만들어 "누구나 쓸 수 있는 도구"로 마무리했다.
